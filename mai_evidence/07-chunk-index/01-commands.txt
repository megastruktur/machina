## Binding design decisions

- **Chunk identity** is `(document_key, ord)`: the parent row is
  revision-specific (schema from `07-vector-schema`), `ord` is the offset in
  the revision's chunk list; the chunker is pure and deterministic, so
  retries re-derive identical identities. Sections: flat ATX-heading grammar
  (every heading starts a section), preamble before the first heading is its
  own section, heading-only sections yield no chunk (empty content is a CHECK
  violation), oversized sections pack greedily at block boundaries with a
  line/character hard split; `MAX_CHUNK_CHARS = 4000`, heading prefix counts
  against the cap.
- **Credential exclusion is structural** (C03 rule 6): fenced blocks whose
  declared info string is in the fixed deny-set (`env`, `pem`, `key`, …) are
  replaced by a fixed placeholder before chunking — keyed on the info string,
  never on content; the test uses deliberately benign content inside a
  denied fence to prove no content scanning in either direction.
- **Embedding seam** is the pinned `openai` SDK surface over the validated
  `06-model-config` `ModelConnection` (base URL gets `/v1` unless already
  suffixed; `credential_ref` resolves through `03-credentials` `EnvResolver`
  at request time; `headers`/`timeout_seconds` flow through). The pinned
  model/dims are this module's frozen constants (`text-embedding-3-small`,
  1536) — never connection settings — so one index can never mix models/dims
  (ADR §4.2 rule-3 refusal is structural: wrong-length responses raise
  `dimension_mismatch` before any write). Batches of 128 preserve order.
- **Reconcile order is embed-first, swap-second**: an unavailable endpoint
  leaves the previous index (stale but answering) plus the durable intent —
  visible pending, never empty-success. The intent is purged only after the
  projection confirms (C02 W4 ack). Deletes are two-phase (tombstone rows +
  remove chunks, commit; purge rows + ack) and every phase is idempotent
  against intent + row state, so a killed indexer restarted mid-batch
  converges (`05-steps` retry discipline; the engine owns the actual wrap).
- **Outbox sweep is per scope** (`read_intents(server_id=…, app_id=…)`);
  cross-scope reads are unrepresentable by construction (doc-store
  confinement). Scope isolation at the storage boundary is the KB-FILTER
  writer-half proof (two servers + shared, per-scope corpora).
- **CLI** consumes `MAI_DATABASE_URL` (`mai.database`) and exits
  0 (reconcile ran — per-intent `status`/`pending` in the JSON lines) / 1
  (structured rejection, value-free) / 2 (usage or IO). Output is value-free:
  no chunk text, no credential material.

   correctly refused; fixed fixture to 0600); hard-split ignored the heading
   prefix so rendered chunks exceeded the cap (chunker bug, fixed);
   embedder tests bypassed `GatewayEmbedder.embed`'s checks by driving the
   SDK directly (test design flaw — tests now call `embed()` through the
   explicit `transport` seam); batch-order assertion indexed within batch.
2. DB round 1: 14 errors — storage tests lacked the `@pytest.mark.anyio`
   marker (repo convention from `test_knowledge_schema.py`; added as
   module `pytestmark`).
3. DB round 2: 6 failed — `_fts_count` used `asyncio.run` inside a running
   loop (made async/await); `_write_doc` lacked `server_id` passthrough;
   delete ack-crash test raised on the first purge call, not the intended
   one (counting fix); scope-isolation test swept only the shared outbox
   (now sweeps each scope, matching the per-scope design).
4. DB round 3: 1 failed → 43 passed (see 02 receipt).
5. Evidence-capture collision (not a product failure): two parallel pytest
   processes re-migrating one fixture database hit
   `duplicate key … alembic_version`; re-run sequentially — 43 + 20 passed.
   The `sessions` fixture re-applies the chain per session by design; a
   single worker per fixture DB is the discipline.

## Limitations

- The `05-steps` durable engine does not wrap this consumer yet; the
  idempotency/crash-window properties are proven at the reconciler boundary
  (commit/ack ordering, two-phase delete) so an engine restart converges —
  the assembled kill-mid-batch journey with the live engine is owned by
  `07-verify` per the registry (KB-FILTER / feature-gate scenario).
- The embedding round trip against a real provider endpoint is pinned
  offline (mock transport) here and owned by `00-verify` (KB-E1); the CLI
  transcript used a local stub server serving the same response shape.
- Chunking parameters (`MAX_CHUNK_CHARS=4000`, `EMBEDDING_BATCH_SIZE=128`,
  the flat section grammar) are this card's frozen contract; the ADR
  deliberately left them open.
- `source_path` is mirrored from `mai.knowledge.documents._paths` (documents.py
  is outside this card's allowlist); a test pins the mirror against the real
  on-disk layout, and the projection CHECK bounds path length.
